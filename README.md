# shipdesign — Проектирование судов: от задания к облику корабля

Статический учебный сайт по теории проектирования судов (ТПС, методика
СПбГМТУ): обратная задача теории корабля — от грузоподъёмности, скорости и
дальности к водоизмещению, главным размерениям и мощности. Живые расчёты в
браузере (ванильный JS, чертежи и графики SVG, без сборки).

**Прод:** https://shadeswd.duckdns.org/design/
(каталог репозитория `shipdesign`, но путь на домене — `/design/`).

## Сквозной пример

Семь разборов задач (`p-*.html`) считают **одно судно** — морской сухогруз
100,0 × 15,3 × 8,3 м, T = 6,60 м, δ = 0,74, Δ = 7659 т, дедвейт 4157 т,
главный двигатель 1980 кВт. Это то же судно, которое строят на соседнем сайте
кластера [«Технология судостроения»](https://shadeswd.duckdns.org/shiptech/)
(секция СК-6 и разбор спуска, спусковая масса 3200 т): два курса говорят об
одном корабле с разных сторон. Здесь объясняется, откуда взялись размерения;
там — как из них получается корпус.

Контрольные числа сквозного примера:

| Разбор | Что считается | Ключевой результат |
|---|---|---|
| `p-mass` | уравнение масс, 5 итераций | Δ = 7659 т, порожнём 3509 т, дедвейт 4157 т, невязка 0,08 % |
| `p-dims` | размерения, надводный борт | F(min) = 1,667 м, T = 6,60 м, α = 0,8485, KM = 6,446 м |
| `p-hold` | вместимость | зерновая 6811 м³, генеральный груз 3405 т, недогруз 595 т |
| `p-power` | сопротивление и мощность | R = 146,0 кН, P(E) = 939 кВт, потребная 1837 кВт, двигатель 1980 кВт |
| `p-stab` | остойчивость | GM = 1,202 м, максимум ДСО 0,929 м, угол заката 67,6° |
| `p-flood` | непотопляемость | затопление МО: 1075 т воды, запас до предельной линии 4,6 см |
| `p-econ` | экономика рейса | 2878 ₽/т, точка безубыточности 2771 т, оптимум скорости 11,5…13 уз |

## Содержание
- `site/` — сам сайт (чистые HTML/CSS/JS, без сборки)
  - `index.html` — обзор курса, спираль проектирования
  - `theory.html` + `t-basics.html` / `t-stages.html` / `t-load.html` /
    `t-form.html` / `t-power.html` / `t-econ.html` — шесть глав конспекта:
    методология и уравнения связи, стадии проектирования и надзор Регистра,
    нагрузка масс и вместимость (Арнотт, Ногид, постатейный метод Бубнова),
    форма корпуса, ходкость и энергетическая установка, экономика и
    энергоэффективность
  - `tasks.html` + `p-mass` / `p-dims` / `p-hold` / `p-power` / `p-stab` /
    `p-flood` / `p-econ` — семь разборов задач с подстановкой чисел на
    сквозном примере
  - `solver.html` — определение главных элементов судна по трём судам-аналогам:
    измерители μ, c, L/B, адмиралтейский коэффициент → водоизмещение,
    размерения и мощность; уравнение нагрузки с запасами и дедвейтом
  - `arrangement.html` — эскиз общего расположения: шпация, переборки, машинное
    отделение, двойное дно/борт, трюмы, бак, ют — с живым чертежом
  - `hullform.html` — теоретический чертёж: строевая по Хоггу с вставкой по
    Линдбладу, грузовая ватерлиния, мидель-шпангоут — с самопроверкой площадей
  - `checks.html` — проверочные расчёты: вместимость, таблицы нагрузки в грузу
    и в балласте, посадка и начальная остойчивость
  - `floodcalc.html` — непотопляемость: предельная длина отсека
  - `sources.html` — источники с выходными данными и сводка того, какие числа
    сайта учебные
  - `assets/`
    - `dcalc.js` — **расчётное ядро разборов**: уравнение масс и итерации,
      размерения и надводный борт, гидростатика по Симпсону, вместимость,
      сопротивление и пропульсивный расчёт, остойчивость и ДСО,
      непотопляемость, экономика рейса. Чистые функции без DOM, работает и в
      браузере (`window.DCALC`), и в node (`module.exports`); есть
      `DCALC.selftest()`
    - `style.css` — стиль сайта (первой строкой `@import url("base.css")`)
    - `base.css`, `shell.js` — **общие модули кластера**, править нельзя:
      мастера в `cluster-infra`, раскладываются `tools/sync-shared.py`
    - `site.js` — данные шапки и один вызов `buildSiteShell()`
    - движки интерактивных страниц: `design.js`, `arrange.js`, `hull.js`,
      `checks.js`, `flood.js`, `shipdraw.js`, `ship-state.js`, `proto-bank.js`
- `deploy/` — docker-compose (nginx:alpine, `127.0.0.1:8068`) + конфиг nginx
- `tests/` — `test_site.py` (целостность сайта) и `test_dcalc.py` (арифметика
  расчётного ядра)

## Стек
Статика: HTML + CSS + ванильный JS, чертежи и графики рисуются прямо в
странице (SVG). Раздача — nginx в Docker с чистыми URL
(`try_files $uri $uri.html $uri/`).

Формулы набираются сырым LaTeX (`\(…\)` в строке, `$$…$$` выключные), а
KaTeX, словарь терминов и хаб кластера **инжектит host-nginx** перед
`</body>`. Поэтому при локальном запуске на `:8068` формулы видны как голый
TeX — это норма, а не поломка. Виджет многокритериального выбора
`/relmet-choice.js` подключается страницей вручную (только `p-power` и
`p-econ`).

## Запуск локально
```bash
cd deploy && docker compose up -d   # проект называется shipdesign (name: обязателен!)
```
Сайт поднимется на `127.0.0.1:8068`. Наружу отдаётся через host-nginx:
`location /design/`.

## Тесты
```bash
pip install pytest --break-system-packages -q
python3 -m pytest tests/ -q
```
`test_site.py` параметризуется по файлам: для каждой HTML-страницы проверяет
разбор, отсутствие дублей `id` и целостность локальных ссылок/ассетов (с
учётом clean-URL nginx), для каждого JS — синтаксис через `node --check`.

`test_dcalc.py` проверяет арифметику `assets/dcalc.js` двумя независимыми
способами: встроенной самопроверкой модуля на аналитически известных случаях
и пересчётом ключевых величин на Python по формулам, выписанным заново, —
чтобы опечатка не могла подтвердить сама себя. Отдельные тесты сверяют числа,
напечатанные на страницах разборов, с тем, что выдаёт модуль.

Сквозная проверка на живом сайте (из `cluster-infra`):
```bash
python3 tools/qa_cluster.py design    # консоль, сырые формулы, ссылки, скролл
python3 tools/qa_all_svg.py design    # выход элементов за границы схем
python3 tools/qa_overlap.py design    # наложения подписей внутри схем
python3 tools/qa_leaders.py design    # пересечения выносных линий
```
